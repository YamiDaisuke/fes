# Debt

Deliberate shortcuts, one line each: what, why, when to revisit.
- App.wasm ships without wasm-opt (10.6 MB, 3.0 MB gzipped): binaryen isn't installed or approved; revisit if installing over cellular is too slow.
- A cancelled pending deploy leaves its PR's check cancelled and can skip that PR's first preview comment: the `pages` concurrency group keeps only one pending job, so restacking three or more PRs cancels some; revisit if restacks often leave PRs without a preview link.
- Background tilemap is a fixed 32×32 cells: map dimensions are a SPEC open decision the owner takes in M4; revisit then (change Tilemap.columns/rows, keep powers of two, re-record goldens).
- One console frame per requestAnimationFrame callback: Safari on iPad delivers rAF at 60 Hz by default, but with the "Prefer Page Rendering Updates near 60fps" feature flag off ProMotion iPads call it at 120 Hz and the game runs at double speed; revisit when input or the cart runtime needs real-time pacing (fixed timestep driven by rAF timestamps).
- The touch overlay is a plain placeholder look, shown in the game view even with a hardware keyboard: the owner styles it; revisit when the owner restyles it.
- The overlay buttons listen only for pointer events, not `click`, so VoiceOver and Switch Control activation does nothing: it is a placeholder pad; revisit when the owner restyles the overlay.
- The boot cart's main.lua is `window.testCartMainLua` instead of the demo's when the page sets it, so Playwright specs can boot their own code without pressing Run or typing through CodeMirror's closeBrackets: revisit if that hook ever ships to users.
- The boot cart's graphics are Swift string art in Runtime/DemoCart.swift: there is no sprite editor to author them as cart files; revisit in M3.
- CPU budget of 500,000 instructions (per frame, and for the main chunk + `_init` together), an 8 MiB memory cap and a 250 ms wall-clock deadline per budget period are placeholders in `Runtime/Budgets.swift`: the owner sets SPEC's numeric limits; revisit when the owner decides them.
- The Lua stack is limited to 15,000 slots (`CLua/fes_lua_user.h`) so a `__call` cycle stops in about 0.2 s in WebKit, which caps recursion at about 1,500–7,500 levels: the stall grows with the square of the limit; revisit if a cart needs deeper recursion.
- One C library call can still freeze the tab, for example `string.find(string.rep("a", 300), ".-.-.-.-b")`, `string.rep("", 1e15)` or `table.move({}, 1, 1e12, 1, {})`: hooks cannot fire inside C, and main-thread wasm cannot be interrupted; a freeze no longer loses unsaved edits, because the recovery copy brings them back after a reload (decision 016); revisit as its own task (fix: run the console in a Worker the page can terminate).
- An endless loop in a `<close>` handler freezes the tab for good when the budget runs out inside a `coroutine.wrap` body, for example `local x <close> = setmetatable({}, {__close = function() while true do end end}) while true do end` (T11 QA-5): the hook's error leaves the coroutine's `allowhook` at 0 and `lua_closethread` runs the handler with no hook; a freeze no longer loses unsaved edits, because the recovery copy brings them back after a reload (decision 016); revisit as its own task (Worker), or sooner if a fix inside the VM is wanted.
- A loop of megabyte string compares or concatenations, such as `while true do local c = a == b end` on 2.5 MB strings, runs up to about 3 s before `CPU budget exceeded` (T11 QA-6): the loop makes no calls, so the clock is read only every 16,000 instructions; revisit if carts hit it, by reading the clock more often on count events.
- When the budget runs out and a `<close>` handler then loops, the error shows `CPU budget exceeded` with no line (T11 QA-7): the cart still stops at once, so the owner deferred finding where the line is lost; revisit with the owner's limits, alongside the usage display.
- CPU and memory errors give no hint of which budget number was hit or how close the cart came: there is no usage display yet; revisit with the owner's limits.
- Saving a cart writes its files one at a time (cart.json last), so a failure partway leaves a mix of new and old files in the folder: OPFS has no multi-file transaction or portable directory move (decision 014); revisit with M6's content-addressed store.
- An import or first save interrupted mid-write (an 8 MiB import takes about 0.7 s, and iPadOS kills background apps) leaves a folder without cart.json that the list shows as "Damaged cart" for good (T15c QA-1): there is no cart deletion; revisit when deleting carts is planned, or with M6's store.
- Edits made before the restore prompt shows are replaced without asking when the user accepts it (T13b QA-2): the window is the OPFS cart listing at boot, a few milliseconds on an iPad; revisit if anyone hits it.
- App icon is placeholder art in scripts/make-icons.js: the owner is a pixel artist; revisit when the owner draws it (edit the grid, run `node scripts/make-icons.js`).
- The Home Screen hint's wording and 7-day reminder are placeholders: revisit when the owner reviews them.
- A .fes re-compressed in Files (Compress) uses deflate and is refused: only store-only zips are read; revisit with DecompressionStream('deflate-raw') if users edit carts in Files.
- Files inside an exported .fes are dated 1980-01-01: no calendar without Foundation; revisit if anyone unzips carts and cares.
- The Art view's look (grid, tile-border, selection and checker colors in Editors/ArtPixel.swift, the tool buttons) is a plain placeholder: the owner styles it; revisit when the owner restyles the editor.
- In a window under about 420 CSS px wide (Slide Over) the Art view cuts off the tile sheet: zoom has a minimum of 1 and the sheet doesn't scroll; revisit if the editor is used in narrow windows.
- In a window under about 676 CSS px wide (Split View, Slide Over) the import report's list wraps under the sticky sheet, which covers rows as they scroll (T25b QA-3): every row is still reachable; revisit if the editor is used in narrow windows, or when the owner restyles the editor.
- In portrait and on iPads with short landscape windows (such as iPad gen 11) the Pixel group sits below the Art tools column's visible area, which scrolls (T18b QA-4): fitting it needs a new tools layout, not a small CSS change; revisit when the owner restyles the editor.
- A cart whose recovery copy is over WebKit's localStorage quota of about 2.5 million characters (a main.lua near 2.4 MB) gets no copy, and the cart status says so on each edit: localStorage is the only synchronous store (decision 025); revisit with M6 history, or if carts grow that large.
- The palette editor's 44 px grids are taller than the middle column in landscape on an 11-inch iPad or an iPad mini, and by about 7 px in portrait on an iPad mini (cutting off the bottom row of main colors), so the panel scrolls; in portrait the Art tools column also scrolls (T20 QA, T21 QA-1): fitting both needs a new Art view layout; revisit when the owner restyles the editor.
