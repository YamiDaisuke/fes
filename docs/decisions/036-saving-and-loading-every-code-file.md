# 036 Saving and loading every code file
Status: accepted (2026-11-15, T33)
Context: Decision 035 lets a cart hold any number of code files and keeps no list of them in cart.json, so a saved cart's OPFS folder is the only record of which code files it has. Load must find them all, and Save must not leave behind a file the cart no longer has, or the next Load brings it back. OPFS has no multi-file transaction (014).
Decision: web/storage.js gains listCartFiles(folder), the names of the files in a cart's folder, and removeCartFile(folder, name), where a missing file is not an error. Load lists the folder, reads each file that is a fixed cart file or whose name ends in .lua in any case, and hands them to Cart(files:), which refuses a bad .lua name instead of hiding it. Other files in the folder are neither read nor removed. Save writes every file, cart.json last, then lists the folder and removes each .lua file the saved cart doesn't have. Removal comes last so an interrupted save never takes a file from the cart as it was; at worst a removed file comes back on the next Load. A failed removal doesn't fail the save: the cart counts as saved and the status says the old file is still there. Import writes to a new folder, so it removes nothing.
Amends: 014.
Alternatives: reading every file in the folder (a stray non-UTF-8 file would stop the cart loading); reading only valid code file names (a damaged name would vanish without a word, which 035 rules out); removing before cart.json is written (an interrupted save would leave the old cart without a file it had); removing only the files the last loaded cart had (misses files left by an earlier interrupted save).
