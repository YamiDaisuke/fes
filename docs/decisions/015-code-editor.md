# 015 Code editor
Status: accepted (2026-11-03, T13a)
Context: SPEC gives the code editor to CodeMirror 6 in JS but says JS never holds cart or editor data. PLAN asks for editor and game as two views with a run button on iPad, where a hardware keyboard both types code and drives the controller. The owner chose two full-screen views, with the game paused while editing.
Decision: web/code-editor.js builds one CodeMirror EditorView (basicSetup, indentWithTab, the legacy Lua mode, autocapitalize/autocorrect/spellcheck off for iPadOS) and hands Swift setCode, onCodeChange and focus as globalThis.fesCodeEditor, created before the wasm starts. CodeMirror holds the document only to show and edit it: every change sends the whole text to Swift, which keeps it in cart.mainLua, and Save, Run and the unsaved check read Swift's copy. setCode replaces the editor state and its undo history and fires no change. Swift owns which view is shown: body[data-view] is "code" or "game", CSS hides the other, and frame() runs the cart only in the game view, so editing pauses the game. Run builds a new RunningCart from cart.mainLua, clears the error, shows the game and focuses the canvas so Enter reaches Start. Code shows and focuses the editor. Loading a cart shows its code without running it and asks before replacing a cart that differs from the one last saved or loaded (the built-in demo counts as saved); a save marks as saved the snapshot it wrote, not later edits. Key routing in web/input.js: a mapped key is the page's when focus is in a text field (input, textarea or contenteditable, which includes CodeMirror) or when it is Enter on a focused button outside the touch pad (pad buttons act only on pointer events). Everywhere else it is a controller button and its default is prevented (issue #39). A ResizeObserver on the game view fits the canvas, including when the view is shown again. The bundle is not minified: CodeMirror adds about 822 KB (203 KB gzipped) next to App.wasm's 3.0 MB gzipped, and readable stack traces matter more.
Alternatives: Swift pulling the text on Save and Run (the editor would hold the only copy of unsaved work in between); sending change sets (more code, carts are small); minimalSetup plus picked extensions (60 KB gzipped smaller, a longer list); JS stopping the frame loop for the editor (JS would own app state); editor and game side by side (the game would be small, owner chose full-screen views); a Cmd+R run shortcut (Safari reloads the page); a beforeunload warning (WebKit on iPadOS doesn't show it, bug 219102); blurring panel buttons after a click (loses the keyboard user's place).
