# 031 Sheet import
Status: accepted (2026-11-13, T24)
Context: PLAN's T24 turns a decoded image into one bank's 256 tiles. The owner chose that tiles use the bank's current sub-palettes and that an import replaces the whole bank (PR #51, answers 8 and 9). PLAN said tiles are "read left to right, top to bottom" and refused "more than 256 tiles", which allows either packing tiles in reading order or keeping each tile's position; they differ for any image not exactly 128 px wide. The owner chose B, keeping each tile's position like PICO-8 (issue #60, question 1), because the 16-wide sheet, the 2×2 and 4×4 edit blocks (decision 026) and spr(n + 16) all depend on it. The pixels come from the browser's decoder (T25) and are untrusted. Tiles don't store a palette, so a tile whose colors fit several sub-palettes needs a rule for which positions its pixels take.
Decision: Editors/SheetImport.swift's Cart.sheetImport(width:height:rgba:bank:preferredPalette:) returns .imported(TileBank) or .refused([SheetProblem]) and changes nothing itself. Whole-image rules run first and stop before any pixel is read: width and height at least 1, multiples of 8, at most 128, and rgba exactly width × height × 4 bytes (at most 65,536). Image tile (c, r) becomes bank tile r × 16 + c, and tiles the image doesn't reach are 0. The at-most-128 rule replaces PLAN's "more than 256 tiles" rule, and PLAN is updated to match. Alpha 0 is transparent whatever its RGB, alpha 255 opaque, anything else refused; transparent is index 0 in the sprite bank and refused in the background bank. Opaque RGB must equal a main palette color exactly, compared as colors so duplicate main colors need no special case. A tile may use 8 opaque colors in the background bank and 7 in the sprite bank. All its opaque colors must be colors of one sub-palette's entries (sprite entries 1–7 only). Palettes are tried preferred first (the Art view's preview palette), then 0–7, and each color takes the lowest position holding it there. A tile's fit is checked only when its pixel rules pass, so the report lists causes, not consequences. Each SheetProblem has a rule, the image tile's 0-based column and row (nil for whole-image rules) and an owner-facing message giving the tile's first pixel. The file type is not an input: T25 adds the JPEG hint.
Alternatives: packing tiles in reading order with up to 256 of any shape (a 64×64 sheet's 2×2 sprites would be split without warning); always trying palette 0 first (a tile in a shared color would take an index meant for another palette); choosing a palette by majority across the sheet (hard to explain); a color tolerance (PLAN refuses it, since it would silently change colors); Swift's Result (a report is not an Error); a separate byte cap (the exact byte count after the size rules already bounds it).
Later: decision 033 makes .imported carry the cart's art after the import (CartArt), so an import that adopts the image's colors returns the same type.
