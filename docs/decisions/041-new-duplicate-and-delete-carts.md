# 041 New, duplicate and delete carts
Status: accepted (2026-11-15, T38)
Context: The shelf (040) could open, export and import carts but not start, copy or remove one, so folders left by an interrupted import or save stayed as "Damaged cart" for good. Deleting is the first action in FES that removes a whole saved cart.
Decision: New cart asks before discarding unsaved changes, then opens a template main.lua named "New cart" with blank art and no folder, counted as saved until edited. Duplicate copies the selected saved cart as stored (every file, not the open cart's unsaved edits) into a new folder named "<name> copy" cut to 64 characters, and selects it. Delete captures the selected folder at the tap; inside the storage queue it looks that folder up in the current listing (doing nothing if it is gone), asks a confirm naming that cart (and its unsaved changes if it is the open one), and only then removes that folder recursively. If it was the open cart the built-in demo opens, which also drops the recovery copy; a failed delete keeps the open cart and its folder, so Save can rewrite it. A listing entry whose cart.json can't be read has no name (not the name "Damaged cart"), and can only be deleted. Save is hidden on the shelf, where the open cart isn't shown. All three actions wait for earlier storage work.
Alternatives: confirming at the tap, outside the queue (a queued save could rename the cart between the question and the removal); reading the name from the button's text (JS DOM as state; a cart named "Damaged cart" would look damaged); duplicating the open cart's edits when it is the selected one (the same button would copy different things); cleaning up a half-written copy automatically (a second code path that removes folders); keeping the deleted open cart's edits as a new unsaved cart (the user just confirmed deleting it); disabling Save on the shelf instead of hiding it (looks broken), or saving the selection (it is already saved).
