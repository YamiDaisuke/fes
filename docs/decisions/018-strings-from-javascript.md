# 018 Strings from JavaScript
Status: accepted (2026-11-05, issue #44)
Context: JavaScriptKit 0.61.0's JSValue.string copies a JS string's UTF-8 into a buffer and decodes it with String(decodingCString:), so it ends at the first U+0000; upstream main is the same. A NUL pasted into the editor cut cart.mainLua, so Run and the check saw only the text before it and Save wrote the cut text (issue #44). Swift to JS is unaffected, because JSString(String) passes a byte length.
Decision: App code reads every JS string through string(from:) in Sources/App/StringFromJS.swift, which encodes it with one shared TextEncoder and decodes the copied Uint8Array with String(decoding:as: UTF8.self); App never reads JSValue.string. A NUL is kept, not refused: main.lua is loaded with luaL_loadbufferx and a byte length, so a NUL inside a string literal works and one elsewhere is an ordinary syntax error, and decision 013 keeps main.lua as written. The other cart files' strict parsers and the name rules already refuse a NUL.
Alternatives: refusing a NUL in the editor (needs the lossless read to see it, plus UI to explain the refusal); fixing only the editor's path (storage reads would still cut text); returning bytes from code-editor.js and storage.js (more JS for the same result); forking JavaScriptKit (a fork to maintain for one line).
