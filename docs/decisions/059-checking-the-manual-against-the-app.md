# 059 Checking the manual against the app
Status: accepted (2026-11-19, T55)
Context: M14's guides tell a beginner which keys to press, what FES answers and which colors a cart starts with (docs/PHASE2.md T55). The names change as tasks rename keys, and a wrong name or color in a guide is a bug the anchor check can't see.
Decision: A key the reader presses is written <kbd data-control>, whose text is the control's accessible name; when the key shows something else (an icon, 1×1), the attribute holds the name: <kbd data-control="1 by 1">1×1</kbd>. Keyboard shortcuts are plain <kbd>; fields, sliders and file tabs are named in the text or as <code>. A name that changes with state is written as it is at boot (Undo, Paint pixel). An answer of the ask dialog that is not also a key (Add, Cancel, Discard, Restore, Replace) is written <kbd data-answer>, since those two buttons are labelled only while a question is open. web/tests/manual-matches-app.spec.js boots the app to the shelf and passes a data-control name only if a button with exactly that accessible name is in the page, hidden views and dialogs included (Playwright's includeHidden). It passes a data-answer name only if it is one of the confirm: and cancel: string literals in Sources/App/*.swift. Each kind is checked against one source, so a key that shares its name with an answer (Rename, Delete) is still looked for in the page. The palette diagram is HTML: .swatch spans with data-main-color and an inline background copied from MainPalette's list. The same spec opens a new cart's palette editor and checks that every manual swatch has the computed color of the app's swatch with that index, and that the diagram covers indices 0 to 63. The Art tools table shows each key's icon with the app's .key .icon-key classes, aria-hidden, beside its name.
Alternatives: opening each question in the spec to read its answers (Replace needs a valid sheet import and Restore a reload: four flows for six words); visiting every view before looking (includeHidden finds hidden buttons and names them); building the diagram in manual.js from a copied list (still hand-kept, and content in JavaScript); an image or a golden screenshot of the palette (can't be checked against the app, or fails on layout instead of color); naming the icon keys without their icons (the keys have no text to match).
