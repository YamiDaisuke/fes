# 032 Importing a sheet in the Art view
Status: accepted (2026-11-13, T25)
Context: PLAN's T25 adds an Import button to the Art view: JS decodes the picked PNG or JPEG with no color-space conversion or premultiplied alpha, Swift validates it with sheetImport (decision 031), a clean sheet replaces the bank after a confirm as one undo step (030), and a refused one shows a report with the offending tiles outlined and, for a JPEG, a hint to export PNG. The file is untrusted: a few KB of PNG can claim 20000 × 20000 pixels, which the decoder would allocate before any check of ours ran. Int is 32 bits in wasm, and a trap kills the app with its unsaved work (004).
Decision: Swift checks file.size ≤ 1 MiB (a 128 × 128 RGBA PNG stored without compression is about 66 KB), reads the bytes, and Editors/ImageFileHeader.swift reads the type and size from the header: PNG's signature and leading IHDR, or JPEG's first SOF marker (C0–CF except C4, C8, CC) found by walking segment lengths; sizes go through Int32(exactly:), since PNG caps them at 2³¹ − 1 and that refuses the same natively and on wasm, and anything else is "not a PNG or JPEG". Those sizes go through sheetSizeProblems (031's size rules, now public); any problem is reported without decoding. Only then does web/art-view.js decodeImage pass the same bytes to createImageBitmap(blob, { colorSpaceConversion: "none", premultiplyAlpha: "none" }), draw it on an OffscreenCanvas and return getImageData; sheetImport checks the decoded size and byte count again. WebKit (2026 source) honours premultiplyAlpha but ignores colorSpaceConversion, so an untagged PNG arrives exactly, alpha 0 and 255 survive the premultiplied canvas, and an ICC-tagged file whose colors get converted is refused as "colors not in the main palette", never silently changed. The bank and preferred palette are the Art view's selection when the pixels arrive. A clean import asks "Replace all 256 <bank> tiles with <file>?" (PLAN keeps a confirm because the wrong bank is the likely mistake), then is one undo step named "sheet import", written to the recovery copy by recordArtEdit after its status. A refused import opens a modal <dialog> titled "Can't import <file>": a JPEG hint when the sniffed type is JPEG, the image drawn at its bank positions on the 16 × 16 sheet grid with each problem tile ringed (aria-hidden, as the list says the same), and one list item per SheetProblem message. Not yet checked on an iPad: whether Pixquare's PNG exports carry an iCCP or gAMA chunk that Safari applies.
Alternatives: decoding in Swift (no inflate, and JPEG needs a full decoder); only a file-size cap (deflate reaches about 1000:1); <img> naturalWidth after load (when WebKit decodes is an implementation detail); trusting the MIME type or extension; WebCodecs VideoFrame.copyTo (more API for the same bytes); no confirm, as decision 030 did for Reset (PLAN asks for one, and an import is the only edit replacing all 256 tiles from outside the editor); the report in the status line (up to 1024 problems) or as a third Art panel (more state); drawing only the image's own tiles (hides where they land).
