# 016 Recovery copy of unsaved code
Status: accepted (2026-11-03, T13b)
Context: With the code editor (015), code typed since the last Save is lost on a reload, a tab iPadOS discards, or a tab a runaway cart freezes (DEBT). WebKit on iPadOS shows no beforeunload warning (bug 219102). The owner chose a recovery copy offered at the next start over autosave, so Save keeps meaning "this is my cart".
Decision: While the open cart differs from the one last saved or loaded, Swift keeps one copy of its main.lua, with its folder and name, as JSON in localStorage["fes-unsaved-code"], written on every edit and removed when the cart matches its saved version again (save, load, undo). localStorage is synchronous, so the copy is written before Run can start Lua and freeze the tab. web/storage.js reads, writes and removes the key; Swift parses it in Storage/UnsavedCode.swift and treats it as an untrusted read: a malformed copy is dropped without asking. At boot FES asks "Restore unsaved changes to <name>?". OK opens the saved cart and puts the copied code over it in the code view, if the folder's cart can be read and still has the copy's name; otherwise the code opens as a new unsaved cart with that name, so Save never writes over a cart the user wasn't shown. In one tab a save or load rewrites or removes the copy, so a different name means another tab or a hand edit changed the folder. Cancel, or a malformed copy, leaves only a copy of edits made since boot, which is usually none, so the key is removed. Only main.lua is copied because it is the only editable part until M3. One key per origin: two tabs share it and the last edit wins.
Alternatives: autosave into the cart's folder (overwrites the saved version with no way back before M6 history; owner chose against it); OPFS for the copy (async, may not finish before a freeze, and overlapping writables can fail); one copy per cart (more to list and clean up for a rare case; M6 history covers it); a beforeunload prompt (not shown on iPadOS); a format number in the copy (short-lived browser state; an unreadable copy is dropped like a malformed one).
