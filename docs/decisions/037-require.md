# 037 require
Status: accepted (2026-11-15, T34)
Context: M10 lets a cart hold more code files than main.lua (035, 036). SPEC: no package library; require is a custom searcher over cart files, name.tl then name.lua, and .tl arrives in M7. Lua errors longjmp past Swift frames (011).
Decision: RunningCart takes main.lua's text and a modules dictionary from file name to text, every code file except main.lua; Runtime still doesn't depend on Storage. require(name) is a C closure whose upvalues are the cart (unretained light userdata, as in 011) and a table of loaded modules that the cart can't reach. It checks the name is a string, returns the stored value if there is one, and refuses a module that is still loading with "module 'x' is still loading (circular require)" at the require call, since Lua 5.4's own require would recurse until "C stack overflow". It looks up name + ".lua" (M7 tries name + ".tl" first), loads it as text with chunk name "=file name", so errors and tracebacks read player.lua:12, marks it loading with a light userdata (pure Lua can't make one, so a module may return any value, false included), calls it with the name and stores its result, or true for nil. require("main") is refused; a missing file reads "module 'x' not found: this cart has no file x.lua". The chunk runs with lua_callk, not a protected call, so the traceback keeps the module's frames; the cost is that a module whose top level raised stays marked loading, and requiring it again after a pcall reports a cycle (DEBT). Every Swift value lives in one helper that only looks up and loads, which can't raise; require's own frame holds plain values when it raises or calls (011). Modules run inside the caller's budget period and under its memory cap, and their sources stay in Swift like main.lua's. Error positions are found by codePosition(inError:files:), the first line of the message or traceback that starts with one of the cart's file names, a colon and a line number.
Amends: 010 (the runtime loads more than main.lua).
Alternatives: stem keys in modules (the M7 .tl lookup and the chunk name would each rebuild the file name); a registry key for the loaded table (an upvalue needs no key); false as the loading marker (a module returning false would look circular); a protected call inside require that clears the marker on error (the traceback would lose the module's frames for every error, to fix a retry after pcall); standard package.searchers (SPEC removes package, and it would bring file-system paths into the sandbox).
