# 024 Drawing without a pointer
Status: accepted (2026-11-12, T18b)
Context: The pencil and picker (023) need a pointer on an aria-hidden canvas (022), but editor accessibility is never cut (CLAUDE.md). VoiceOver on iPadOS adjusts a native range input with a swipe but sends a canvas or a role=slider div no events (022).
Decision: A Pixel group in the tools column holds two native range inputs from 0 to 7, Pixel column and Pixel row, whose aria-valuetext Swift sets to the value and the color index under the cursor ("3, color 5"), and a button that applies the current tool at the cursor, labelled "Paint pixel" or "Pick color" by Swift. ArtSelection holds the cursor. Painting is a one-point stroke and picking returns to Pencil, as in 023. While focus is inside the group, the edit area draws a white ring around the cursor pixel, the same ring the sheet draws around the selected tile. Both sliders are horizontal, so → and ↑ raise the row like the column; a swipe up raises either with VoiceOver. Swift replaces the button's text only when the tool changes, because WebKit sends no click when the pressed text node is replaced between mousedown and mouseup, and focusing the button redraws.
Alternatives: arrow keys on a focusable canvas (it is aria-hidden, and VoiceOver wouldn't pass them); 64 pixel buttons (64 swipe stops, 1,024 with T20's 4×4 blocks); one slider over all pixels (8 presses to move down one row); always showing the cursor (clutter while drawing by touch); a vertical row slider so ↓ moves down (vertical ranges need writing-mode, only in Safari 17.4 and later, and their arrow-key direction differs between engines).
