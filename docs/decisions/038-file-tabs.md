# 038 File tabs
Status: accepted (2026-11-15, T35)
Context: A cart holds main.lua and up to 31 other code files (035), and the Code view has one CodeMirror editor (015). The user must move between files without losing undo history or their place, errors must be shown in the file they come from, and JS may hold cart text only to show and edit it (SPEC, 015).
Decision: A tab strip above the editor (role tablist, one button with role tab per code file, in cart order) shows which file is open. Swift holds the shown file's name, starts at main.lua whenever a cart is opened, loaded or restored, keeps it across Run, and moves it to the file a runtime error names. web/code-editor.js keeps one EditorState and scroll snapshot per file name, so undo, cursor and scroll survive switching; it reuses a stored state only when its text equals Swift's, and Swift has it forget them all when a cart's code is replaced, so undo never brings back another cart's text. Every syntax check (half a second after an edit, on Run, on opening) checks the shown file first, then the others, so a message about a broken file stays until that file is fixed. Swift keeps the latest error and, after every switch, marks it in the editor only when the error's file is the one shown, because stored states keep stale diagnostics. The strip is one row that scrolls sideways, so 32 files on an iPad mini in portrait cost the editor no height; the shown tab is scrolled into view. Keyboard: only the shown tab is in the Tab order; Left, Right, Home and End move between tabs and switch files at once (WAI-ARIA tabs, automatic activation). Tapping a tab doesn't focus the editor, so the on-screen keyboard doesn't open when the user only wants to read.
Amends: 015 (one stored editor state per file), 017 (all files are checked; the mark follows the shown file).
Alternatives: one EditorView per file (32 views to keep in step); recreating the state on every switch (loses undo); JS tracking the selected tab (JS would own editor state); checking only the shown file (typing elsewhere would clear a message about a file that is still broken); wrapping tabs (up to eight rows on an iPad mini, taking the editor's height); a select menu (hides the files); every tab a Tab stop (32 presses before the editor); manual activation (an extra key for an instant switch); a tabpanel role (repeats the editor's own label).
