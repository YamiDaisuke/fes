# 055 The CRT filter
Status: accepted (2026-11-17, T51)
Context: SPEC's Display bullet left room for "an optional CRT/LCD shader" in WebGL. M13 asks for an optional CRT look on the game screen (docs/PHASE2.md, T51). The owner chose off by default (decision 6, issue #120).
Decision: The filter is a CSS overlay, #screen-crt, in one grid cell with the game canvas inside #screen-glass, so its box is the canvas's box at every scale and on the same whole pixels (047). It never touches the canvas, the framebuffer or the frame loop, and labels are still captured from the framebuffer. It has position: relative because WebKit paints a composited canvas over a later non-positioned sibling. fitCanvas sets --screen-scale on #game-view. One console pixel is a background tile of --screen-scale px, and each stripe is a third of it rounded to whole px (at least 1 px), so every hard stop is on a whole CSS pixel. There are three layers: a vignette (radial, up to 35% darker at the corners; the one soft gradient, because it is glass), scanlines (the bottom band of each console row 25% darker) and an aperture grille (red, green and blue bands at 8%). Below 3× fitCanvas leaves data-scanlines off and only the vignette shows, because a whole-pixel band would cover half of each row. The colours are the --crt-* tokens. They are translucent, so they stay out of look.html's opaque token list. The switch is a CRT key (aria-pressed, the key's own LED) in the bezel strip between the power LED and the FES badge. It is a device preference, so JavaScript owns it: body[data-crt], localStorage key fes-crt ("on" or "off"; anything else reads as off), default off. It is read before the first frame through web/preferences.js, the guarded read and write that pwa.js shares (T27). The filter shows only on the game screen. It has no animation, so reduced motion needs nothing.
Amends: SPEC Display bullet; 047 (the bezel strip holds a key, and aria-hidden moves from the strip to the LED and the badge).
Alternatives: a WebGL shader (a second renderer, and pixel tests that read the canvas would have to know about it; it can replace the overlay later behind the same key); an absolutely positioned overlay sized from the scale (ties it to the bezel padding and the screen size); fractional stripe stops (anti-aliased, soft rows); the bezel's extra stepped corner cut while the filter is on (a second polygon token, and a switch that reshapes the plastic); a flicker (tiring, and a composite every frame on the iPad); the key in the toolbar or the pad row (not part of the screen).
