# 039 Adding, renaming and deleting code files
Status: accepted (2026-11-15, T36)
Context: The Code view must let the user add, rename and delete code files (035) with the touch screen, the keyboard and VoiceOver, without JS owning cart state (015). T33 QA found that with 036's save order a removal that fails leaves the dropped file in the folder, so a full cart can reach 33 .lua files there, and Load refuses it with no way in the app to fix it.
Decision: A "File actions" group after the tab strip (outside the tablist, which may hold only tabs) has New file, Rename and Delete buttons; Rename and Delete act on the shown file and are disabled while main.lua is shown. Names are asked with prompt and deletes confirmed with confirm until T45. The typed text is lower-cased and gets .lua unless it ends in it; the Storage mutators decide, and a refusal is shown in the cart status as "Can't add player.lua: this cart already has it" and changes nothing. Success is announced in the same status. A new file opens empty, shown, with the editor focused; a renamed file keeps its text and the tab, loses its undo history (its stored editor state is forgotten under the old name), and require calls naming it are not rewritten or warned about, since the runtime "not found" error names the file; deleting shows main.lua and moves focus to its tab. Every change rebuilds the tabs, writes the recovery copy and rechecks syntax; unsaved is still cart != lastSavedCart. Save now lists the cart's folder and removes the .lua files the cart doesn't have before writing anything, and a failed removal fails the save, so a folder never holds more code files than the cart being saved and a dropped file can't come back on Load. listCartFiles of a missing folder is empty, as readCartFile of one is null.
Amends: 036 (removal comes first and is no longer best effort).
Alternatives: buttons inside the tablist (invalid ARIA, and the arrow keys belong to the tabs); aria-disabled as in 030 (only Delete loses focus, and it has a natural place to send it); keeping undo history across a rename (needs a compartment to relabel the editor); warning about require calls naming a renamed file (a regex over Lua source guesses); removing last and retrying (a removal that keeps failing still locks the cart out); checking the limit on the files the cart keeps (needs a manifest, 035); removing first only when the folder would pass 32 (two paths, the rare one untested); letting Load ignore the limit (weakens validation of storage reads). Cost: an interrupted save can leave the old saved cart without a file it had; the recovery copy still holds the cart being saved.
