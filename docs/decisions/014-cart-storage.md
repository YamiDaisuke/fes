# 014 Cart storage in the browser
Status: accepted (2026-11-03, T12b)
Context: SPEC puts the cart format and logic in Swift and gives JS a small async OPFS wrapper. Swift must await browser promises. OPFS fails in Safari Private Browsing and in Playwright's default WebKit context (getDirectory() throws UnknownError; a persistent context works), and several files can't be written as one step.
Decision: web/storage.js has four stateless async functions over OPFS carts/<folder>/<file>: listCartFolders, readCartFile (UTF-8 with fatal decoding, null if missing), writeCartFile (createWritable, which commits on close) and requestPersistentStorage. Swift awaits them with JavaScriptKit's JavaScriptEventLoop and owns the open cart, its folder and the list. Folders are 16 random hex digits; names live only in cart.json, and an unreadable folder is listed as "Damaged cart" rather than hidden. Save writes cart.json last. persist() is requested once at boot. Without OPFS, saving is turned off with a status message and the console keeps running. Playwright storage specs use launchPersistentContext.
Alternatives: JS orchestrating save and load (JS would own the open cart); JSPromise.then callbacks (nested callbacks for the list); cart names as folder names (escaping, renames move folders, duplicate names); hiding damaged carts (looks like data loss); persist() after the first save (only matters in browsers that prompt); write to a temporary folder and swap (OPFS has no portable directory move; M6's content-addressed store makes saves whole).
