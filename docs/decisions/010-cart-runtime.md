# 010 Cart runtime
Status: accepted (2026-10-31, T09)
Context: SPEC lists the sandbox libraries and says Lua errors stop the cart with an on-screen message, but not which base functions stay, how load refuses bytecode, how an error becomes text without a second error escaping a protected call (an unprotected Lua error aborts the app), where the message shows before the console has a font, or what missing callbacks mean.
Decision: Runtime's RunningCart owns one lua_State per cart (a class, so deinit closes it once). It opens base, string, table, math, utf8 and coroutine, then removes dofile and loadfile (SPEC), print and warn (stdout/stderr nobody sees on iPad; the console API owns print), and string.dump (nothing can load its output); io, os, package and debug are not compiled (decision 001), and require comes with multi-file carts. A Lua wrapper replaces load and always passes mode "t", forwarding env only when given; main.lua loads with mode "t" as "=main.lua", so errors read "main.lua:8: message". The main chunk runs, then _init; runFrame calls _update then _draw. Callbacks are fetched with rawget from the globals table kept at stack index 2, every frame; nil is skipped, other non-functions are called and error. Every call is lua_pcall with lua.c's msghandler (stack index 1): non-string error objects go through __tostring inside the protected call, then luaL_traceback appends the stack; a __tostring that rethrows ends in "C stack overflow", checked natively and in WebKit. The first error is kept and nothing runs after it. App writes it once, from Swift through JavaScriptKit, into <pre id="cart-error" role="alert"> over the canvas.
Alternatives: text in the framebuffer (needs a console font, which comes with the overlay layer's print; 48 characters per line; invisible to VoiceOver); JS reading the message from wasm memory (a second export and JS logic about console state); lua_getglobal for callbacks (a strict-mode __index on _G raises unprotected and aborts); a Swift C function replacing load (re-implements luaB_load's argument handling); keeping print to stdout; calling callbacks again after an error (repeats it every frame).
For T11: the capped allocator and count hook attach in RunningCart.init; allocations made outside lua_pcall (sandbox setup, callback names) must not fail on the cap, or the memory error is unprotected.
