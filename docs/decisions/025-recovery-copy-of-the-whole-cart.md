# 025 Recovery copy of the whole cart
Status: accepted (2026-11-13, T19)
Context: Decision 016's recovery copy held main.lua and the name, so since the pencil (023) tile edits made after the last Save were lost on a reload, a discarded tab or a frozen tab. Copies written by that FES must still restore. localStorage is the only synchronous browser storage, and WebKit allows an origin 5 MB of it counted in UTF-16, about 2.5 million characters (WebKit bug 245479).
Decision: localStorage["fes-unsaved-code"] (the key keeps its name so older copies are found) holds {"folder": ..., "files": {file name: text}}, the open cart's Cart.files, with no folder for a cart never saved. It is kept while the open cart differs from the one last saved or loaded (cart != lastSavedCart, the Load prompt's test) and removed when they match. It is written once each edit that changes the cart is complete: every code change, the end, cancel or drop of a pencil stroke (Run drops a held stroke before Lua starts), and every Paint pixel press; never on a pointermove. Later Art edits follow the same rule. Storage/RecoveryCopy.swift reads it as untrusted input: the files go through Cart(files:), so a copy that would not load as a saved cart is dropped without asking. A copy with "name" and "mainLua" instead of "files" was written by the older FES and restores as 016 did, its code and name over the saved or boot cart. 016's folder rule holds for both: the copy goes back to its folder only if the folder's cart reads and has the copy's name, and otherwise opens as a new unsaved cart. Size: the files other than main.lua take about 38,500 characters as JSON, so a cart with a 64 KB main.lua uses about 4 % of the quota, and a write fails only when main.lua nears 2.4 million characters. When a write fails, FES removes the previous copy and says so in the cart status, so a copy is never older than the last Save. Cost: keeping the copy takes a median of 1.2 ms (worst 2.4 ms) per keystroke with a 64 KB main.lua, and 0.7 ms (worst 1.6 ms) per keystroke or 0.7 ms (worst 1.95 ms) per stroke end with the demo cart, over three runs of 50 in Playwright's WebKit on a 4-core 2.1 GHz cloud VM; not yet timed on an iPad. Nearly all of it is building the text, so jsonString and tileSheetText fill a byte buffer and decode it once instead of appending to a String per character (which took 6.1 ms per 64 KB keystroke); the output is unchanged.
Alternatives: a version field (the shape tells the two copies apart, and cart.json inside the files carries the cart format; 016 already rejected a number); file names as top-level keys (no JSON reader change, but mixes folder with file names); one key per file, writing only changed files (less written per keystroke, more keys to keep consistent and clean up; revisit if writes get slow); one key per file to cut the per-keystroke cost (the cost was string building, not storage: setItem took 0.1 ms); writing on pointermove (up to 240 writes a second with Pencil); keeping the old copy when a write fails (it could put older work over a newer save); compression (unneeded at 4 % of the quota).
