# 017 Live diagnostics
Status: accepted (2026-11-05, T14)
Context: SPEC feeds CodeMirror's diagnostics from the compiler running in wasm, and PLAN asks for syntax errors on the right line within a moment of typing and runtime errors that jump to their line. JS may not own the code (decision 015), the running cart's state carries the game's budgets (decision 012), and on iPad there is no hover to reveal a message.
Decision: Half a second after the last edit, a JSTimer in Swift compiles cart.mainLua in a new lua_State made with the capped allocator, with the same luaL_loadbufferx call, chunk name, text-only mode and memory cap as Run, then closes it; no Lua code runs, so no sandbox or count hook is needed, and a check fails exactly when Run's load would. Replacing the code (boot, load, restore) checks at once, because setCode starts a new editor state without diagnostics. The error's line is the first line of its text, ignoring leading tabs, that starts with "main.lua:<n>:", so errors without a position use the traceback's first main.lua frame; budget errors without a line get no diagnostic. Swift pushes at most one error to fesCodeEditor.showError(line, message), which sets one whole-line @codemirror/lint diagnostic with setDiagnostics and a gutter marker, and writes the error's first line into <p id="code-error" role="status"> only when it changes, so touch and VoiceOver users get the message without hover and a repeated error isn't re-announced. A runtime error moves to the editor when the user presses Code: its line gets the diagnostic and the cursor, and the next syntax check replaces it. Run is the only way back from the code view, so the error always belongs to the code shown.
Alternatives: the running cart's lua_State (allocates in the game's heap, gone or replaced on Run); luaL_newstate (uncapped, disagrees with Run on huge carts); checking every keystroke (flags half-typed lines); debouncing in JS (JS would decide when code is checked); CodeMirror's linter() pull source (a JS-owned timer and source); the auto-opening lint panel (takes editor height on every error); switching to the code view on a runtime error (takes the stopped screen away from the player); a go-to-line button in the error overlay (the Code button already leads there); keeping runtime and syntax diagnostics together until the next Run (merging lists for little gain).
