# 022 Art view
Status: accepted (2026-11-05, T17)
Context: PLAN's M3 adds an Art view next to Code and Game (decision 015). Swift renders a bank's 16×16 tile sheet and a zoomed edit area with a pixel grid, and JS only blits them and forwards taps. The owner chose one full-screen view, with the sheet on the left, the edit area in the middle, and tools, colors and palettes on the right (PR #51). VoiceOver and a hardware keyboard must be able to read and change the selected tile, and the canvases must fit every iPad size and orientation.
Decision: A new Editors target (Console and Storage, no browser) holds ArtSelection (bank, preview palette, tile), each bank's preview colors (sprite color 0 is nil, drawn as transparent per decision 008), GridLayout, and the two renderers, which return an RGBAImage of any size. A GridLayout is n squares per side with 1-pixel lines between and around them. The sheet is 16 squares of 8 art pixels and the edit area 8 squares of 1, so its grid is the pixel grid. Its zoom is the largest integer, at least 1, at which the image fits the box CSS gives the canvas. The image is shown at one CSS pixel per image pixel, so the browser only doubles it for Retina with image-rendering: pixelated, and lines stay thin at every zoom. A canvas pixel p maps to square max(p − 1, 0) / (squareSide + 1), so a line belongs to the square before it. Positions outside the image, or not integers, are ignored. Transparent pixels are a 2×2 checker of two grays per art pixel. The selected tile has a white ring in the grid lines around it. These colors are placeholders in Editors/ArtPixel.swift. Swift owns the selection and renders only while the art view is shown and something changed: the view was shown, the selection, bank or palette changed, or a ResizeObserver created by Swift reported a resize. Swift sets the canvas size and calls fesArtView.blit(canvas, address) inside withUnsafeBytes. blit wraps the bytes in place as in decision 007, so nothing is copied and the address is never kept. web/art-view.js turns a pointerdown into a canvas pixel with getBoundingClientRect and calls Swift's listener. The canvases are aria-hidden. The accessible control is a native range input from 0 to 255 labelled Tile, whose aria-valuetext Swift sets to "17, column 1, row 1", counting from 0 as spr does. Bank and preview palette are buttons whose aria-pressed Swift sets. body[data-view] gains "art". frame() runs the cart only in the game view, so Art pauses the game like Code does, and Run is still the only way into the game view. Leaving the game view, to Code or Art, moves its runtime error into the editor once, instead of pressing Code, so a previous run's error never lands on code edited since (this updates decision 017). Save and the cart status move from the code view's panel to the toolbar, so they are reachable from every view; the name stays in the panel. In landscape the layout is three columns (sheet, edit area, a 256 px tools column). In portrait, by an orientation media query that also covers narrow Split View windows, the edit area spans the top and the sheet and tools share the bottom.
Alternatives: copying pixels into a JS typed array on every render (a megabyte per pointer move once T18 paints); JS pulling the images every frame (JS would decide when to redraw); a fixed buffer scaled by CSS (lines and the ring would grow with the scale); rendering at device pixels (devicePixelRatio in layout and hit testing for no visible gain); a selection rectangle in HTML over the canvas (positioned in two places and missing from the goldens); alpha-0 transparent pixels over a CSS background (they look like the page's black, which Z64 also has); 256 buttons over the sheet (VoiceOver would swipe through 256 stops); an ARIA slider on the canvas (VoiceOver on iPadOS sends a role=slider div no events, while it adjusts a native range with a swipe up or down); a second Save button in the art view (its status would still be hidden in the code view); still moving the error when Code is pressed (code → Art → Code would put an old error back on edited code).
Later: decision 023 adds strokes in the edit area, the tool and color controls, and a redraw at most once per animation frame while drawing.
