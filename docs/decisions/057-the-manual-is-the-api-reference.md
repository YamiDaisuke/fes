# 057 The manual is the API reference
Status: accepted (2026-11-18, T53)
Context: docs/API.md described every Lua call, and M14's manual must describe them for beginners too. Two hand-kept copies drift. The owner chose the manual as the one source (PHASE2 decision 8, issue #122).
Decision: The API reference is the api section of web/manual/index.html, and docs/API.md is a short pointer to it. The section opens with three subsections whose ids don't start with api- (rules-for-every-call, when-things-show, budgets-and-errors), then has one section per console global with id api-<name>; only call entries use that prefix. Each entry has the name as its heading (not uppercased, since Lua names are case-sensitive), the signature, one sentence, a parameter table (name, meaning, range, default) or "Takes no arguments", what it returns, an example and, where there are some, common mistakes. An example that is a whole one-file cart is a pre with data-example="api-<name>". web/tests/manual-examples.spec.js runs every pre[data-example] in the manual on the demo's art for 60 frames with → and A held, then 60 with ← held, so code behind btn and btnp runs too, and fails on a cart error. An example that reads other buttons adds them to that spec. web/tests/api-reference.spec.js boots a cart that collects every function in _G not defined by Lua 5.4's base library (lbaselib.c's base_funcs) and stops with that sorted list as its error message. The spec compares the list with the manual's api- ids in both directions. require is on the list because FES's require is its own (decision 037), not Lua's package library. A task that adds, removes or changes a call updates its entry in the same PR. The budget's deep details (pcall and xpcall once the budget is spent, __gc, the wall clock) sit in a closed "For the curious" details. Links to other sites open in a new tab (target="_blank" rel="noopener"), so the Help iframe never navigates away from the manual.
Amends: 011 (the reference lives in the manual, not docs/API.md).
Alternatives: keep docs/API.md and generate the manual from it (a Markdown build step for one page); keep both by hand (they drift); have the cart place one sprite per name for the spec to read (a name-to-position table on both sides and pixel reads); inject the documented list into the cart and compare in Lua (a mismatch shows as a Lua string instead of Playwright's diff); untested fragments as examples (an example with a wrong argument would ship).
Later: amended by decision 058 (examples with several files carry data-file and are tested too; the spec also holds ↓ and ↑).
