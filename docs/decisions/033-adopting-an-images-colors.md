# 033 Adopting an image's colors
Status: accepted (2026-11-14, T26)
Context: PLAN's T26 adds an import option: the image's colors (up to 64, in order of first appearance) become the cart's main palette, and the bank's 8 sub-palettes are built from the tiles' color sets; images over 64 colors, or needing more than 8 sub-palettes, are refused through 031's report, and the confirm says the other bank's colors change too. Which tiles share a sub-palette is bin packing with overlapping sets, which has no fast exact solution. The other bank's sub-palettes hold main palette indices (004), so a new main palette recolors it.
Decision: Editors/SheetImportAdoptingColors.swift's Cart.sheetImportAdoptingColors(width:height:rgba:bank:) runs 031's whole-image rules, then collects the image's alpha-255 colors in reading order; more than 64 is refused as one whole-image problem giving the count. Image color i becomes main color i; later main colors keep the cart's (duplicates are allowed, 021). Editors/SubPalettePacking.swift's packSubPalettes takes each tile's distinct opaque colors, skips empty sets and sets over the tile limit (8, or 7 for sprites), and goes largest set first (ties in tile order): a set joins the existing sub-palette it fits that needs the fewest new colors (lowest number on a tie), appending them in tile order; otherwise it opens a new sub-palette while fewer than 8 exist; otherwise it is left out. Sprite sub-palettes fill entries 1–7, so entry 0 stays transparent; every entry no tile needs is main color 0. The bank's sub-palettes are replaced, then 031's sheetImport runs on that adopted cart with preferred palette 0, so the per-tile rules and the pixel mapping are the same code; a tile fitting no sub-palette is reported as needing more than 8. The other bank's tiles and sub-palette indices are untouched, so its colors become what the new main palette holds there. Both imports return .imported(CartArt), the cart's art after the import, and the App applies either with cart.art = art as one "sheet import" undo step (030's snapshots already include the main palette and both banks). The Art view has "Import sheet" and "Import sheet and colors", which open the same file picker; Swift remembers which was pressed. The second's confirm names the bank's tiles, its palettes and the main palette, and says the other bank's tiles may change color.
Alternatives: an exact packing search (exponential worst case, harder to read; the greedy only fails sheets already at the limit, and the report shows which tiles); first fit in tile order (a small set placed early can fill a palette a later large set needed); main colors in tile order (reading order is what first appearance means in a picture); filling unused main colors with black or Z64 (discards the other bank's colors for nothing); keeping old indices or PaletteBank's spread in unused entries (they would look like real palettes in unrelated colors); remapping the other bank to the nearest new colors (automatic color reduction, which M3 rules out); a second result type or a third SheetImport case (two near-identical switches in App, or a case one function never returns); a checkbox (it persists, so a later import could replace the main palette by surprise) or a choice dialog after picking (more UI for the same choice).
