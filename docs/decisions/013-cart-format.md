# 013 Cart format
Status: accepted (2026-11-03, T12a)
Context: SPEC keeps cart files text-based for diffs, history and a later git export, and leaves the format details to the owner, who chose them in issue #12. The format is permanent once carts exist.
Decision: A cart is a folder of files: cart.json ({"format": 1, "name": ...}, pretty-printed with sorted keys), main.lua, background.tiles and sprites.tiles (a 128×128 sheet of digits 0–7, tile n at column n % 16, row n / 16), palettes.pal (16 lines of 8 two-digit hex master indices: background palettes 0–7, then sprite palettes 0–7) and map.map (32 lines of 32 space-separated cells: two hex digits of tile, then one palette digit). Hex is written lowercase and read in either case. Storage converts a Cart to file name → text and back; it reads LF or CRLF and writes LF with a final newline. Every file must be present and exactly shaped, or the whole cart is refused, naming the file and line. Unknown files and unknown cart.json keys are ignored. format is one integer bumped by any format change: a newer FES upgrades older carts on load, and an older FES refuses newer carts. Names are 1–64 characters without control characters. cart.json is read and written by a small strict JSON reader and writer in Storage (Sources/Storage/JSON.swift), which also refuses duplicate keys; the owner chose it in T12b (issue #35) because Foundation's JSON coding added about 9.3 MB raw, 2.3 MB gzipped, to App.wasm.
Custom extensions: git and GitHub detect text by content, so these files show and diff as text without a .gitattributes entry. The iPad Files app can't preview them; open them in a text editor through the share sheet. Accepted for the clearer names.
Sharing (input for T15): a cart is shared as a zip of this folder, files at the top level, named <cart name>.fes. T15 must check on iPad that the import picker can select .fes files (drop the accept filter if iPadOS greys them out), that downloads keep the .fes extension, and how a user can unzip one in Files (renaming it to .zip). iPadOS does not let a web app register a file type, so .fes files open through FES's import button, not from Files.
Later: M3 adds a per-cart master palette as its own file, with a format bump; format 1 carts use the built-in palette.
Alternatives: per-tile blocks or packed hex for tiles (art spanning tiles can't be seen, or nothing is readable); decimal numbers (ragged columns); one graphics file with sections (history can't tell which part changed); .txt names (previewable, but the owner preferred names that say what each file is); major.minor versions (a judgement call per change, and older saves drop newer data); defaults for missing files (hides corruption and makes it permanent on the next save); Codable through FoundationEssentials (used in T12a, but about 9.3 MB of App.wasm).
