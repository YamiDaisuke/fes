# 044 Booting into the shelf
Status: accepted (2026-11-16, T41)
Context: The owner chose (decision 2 of docs/PHASE2.md, issue #110) that FES opens on the cart shelf instead of running the demo. The shelf is now the first screen, so its demo picture must be there at boot even when storage can't list carts, and Playwright specs that boot their own code through window.testCartMainLua expect the game.
Decision: index.html starts with data-view="shelf" and shownView starts as .shelf; nothing is selected and nothing is focused, so VoiceOver and Tab start at the top of the page (toolbar, install hint, shelf). When window.testCartMainLua is set, main.swift ends with show(.game), so those specs boot into the game as before. A recovery copy restored at boot still shows the Code view. boot.js loads the wasm through JavaScriptKit's instantiate() with instrumentInstance instead of init(), so fesArtView has the wasm memory before main() runs: the list built at boot draws the demo's picture, and showShelf() only shows and focuses.
Alternatives: focusing the demo entry at boot (skips the install hint for VoiceOver, and no focus is lost that needs a new home); selecting the demo at boot (changes the shelf's tap-to-select rule; left for later); a separate test hook for the boot view (every spec that boots its own code wants the game); drawing the demo's picture after the boot storage task (races boot.js setting the memory when storage fails fast) or on the first shelf frame (a drawn-yet flag); keeping init() and redrawing on show (blank demo picture on the first screen whenever storage fails).
