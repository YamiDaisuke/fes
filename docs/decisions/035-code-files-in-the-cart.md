# 035 Code files in the cart
Status: accepted (2026-11-15, T32)
Context: M10 (docs/PHASE2.md) lets a cart hold more Lua files than main.lua so carts can require modules. The cart format is permanent once carts exist (013), and files reach Storage from OPFS, a .fes archive and the recovery copy, all untrusted.
Decision: A cart's code is Cart.codeFiles, main.lua first and always present, the rest sorted by name; only Storage changes the list, through addCodeFile, renameCodeFile and removeCodeFile, which return a problem string and refuse renaming or removing main.lua. A code file name is a stem of 1–32 characters from a–z, 0–9 and _, not starting with a digit, plus .lua; lower case only, because the stem is the module name and an unzipped cart may land on a case-insensitive file system. codeFileNameProblem (Storage/CodeFiles.swift) is the only place these rules live. A cart holds at most 32 code files, main.lua included. There is no manifest: the code files are whichever of the cart's files have valid code file names, so cart.json doesn't list them. A file whose name ends in .lua in any case but isn't a valid name is refused, never ignored, so code can't silently vanish from a cart; in a .fes this covers folder prefixes and upper case, and a name that would unzip in place of a code file reads "could be unzipped as" like the fixed files (020). Other unknown files are still ignored. Every code file gets main.lua's text rules: one leading byte order mark dropped (034), CRLF and lone CR read as LF (013). Export writes the fixed files in their old order, then the other code files in sorted order. cart.json is format 3; formats 1 and 2 load unchanged, since they hold only main.lua, and save as 3; an older FES refuses a format 3 cart with its "made with a newer FES" message.
Amends: 013 (cart files) and 020 (which archive entries are read or refused).
Alternatives: a file list in cart.json (the JSON reader has no arrays, the list could disagree with the folder, and the sort fixes the order anyway; the cost is that a save must delete removed files, T33); folders (paths in a zip and in OPFS bring traversal and case problems for no need yet); mixed-case names (two files that differ only in case collide in Files); ignoring bad .lua names as other unknown files are (a require then fails with no hint and the next save drops the file); a special case for __MACOSX/ entries (Finder's Compress deflates, which FES already refuses).
