# 043 Labels and the D-pad on the shelf
Status: accepted (2026-11-16, T40)
Context: The shelf (040) listed carts by name. M11 gives each entry its label picture (042) and lets the controller pick carts, and listing the shelf must stay cheap with many carts.
Decision: Each entry is a button holding a 192×144 canvas and the cart's name; the canvas is aria-hidden, so the name alone is the button's accessible name. Rebuilding the list (boot, save, import, duplicate, delete) reads, per saved folder, cart.json, label.hex and, only when there is a label, main-palette.hex; Swift renders the label with that palette into an RGBAImage and fesArtView.blit draws it, all before the list is replaced so it never flashes blank. Selecting, moving and showing the shelf redraw nothing. A missing, unreadable or malformed label or palette leaves the picture blank; the entry keeps its name and actions, and loading reports the bad file as for any cart file. The demo's picture is its first frame, rendered once on first use. In the shelf view the controller (arrows, Z, X on a keyboard) acts on the list: Left and Right move the selection one entry in list order, starting from the selected entry or from the first when none is, stopping at the ends; the entry moved to gets focus and is scrolled into view; A plays and B edits the selection when Play and Edit are enabled. frame() keeps Input's edges in every view, so a button still held when the view changes never counts as a new press.
Alternatives: role="img" with a label on the canvas (the button's name would no longer be the cart's name); drawing each label as it is read (every refresh blanks and refills the shelf); caching rendered labels per folder (invalidation on four actions for a cost that only shows with many carts); a checked-in demo label.hex (goes stale when the demo changes); starting the D-pad from the focused entry (Safari doesn't focus a tapped button); marking a cart with a bad label as damaged (its code and art may be fine).
