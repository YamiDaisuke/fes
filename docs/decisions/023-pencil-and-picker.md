# 023 Pencil and picker
Status: accepted (2026-11-12, T18a)
Context: PLAN's T18 paints the selected tile with the preview palette's colors by finger or Apple Pencil (owner, PR #51), draws continuous lines on fast drags, adds a color picker, and puts edits in the open cart. Decision 022 has JS forward canvas pixel positions while Swift owns the art and the redraws. WebKit sends pointermove at the digitizer's rate (up to 240 Hz with Pencil), not aligned to animation frames (WebKit bug 210454); getCoalescedEvents exists since Safari 18.2 but its coalesced events have no pointerId or target. Once the Pencil touches, iPadOS stops sending finger events, but a palm that lands first arrives as a touch.
Decision: ArtSelection gains the tool (Pencil or Picker) and the color, an index 0–7 into the preview palette that defaults to 1. The tools column has Pencil and Picker buttons and a strip of the preview palette's 8 colors labelled "Color n" ("Color 0, transparent" in the sprite bank), with aria-pressed and the swatch colors set by Swift. web/art-view.js onStroke owns one pointer at a time: a primary-button pointerdown captures the pointer and sends "start" with its canvas pixel; that pointer's pointermoves send "move" with every coalesced position, or the event's own when there are none; pointerup sends "end" and pointercancel "cancel". Other pointers are ignored during a stroke, except that a pen pointerdown during a non-pen stroke sends "cancel" and starts the pen's stroke, because a palm usually lands before the Pencil. A hovering Pencil is ignored because no stroke is active. Swift maps a position to an edit-area pixel with 022's grid rule extended past the edges (a pixel can be -1 or 8) and draws a Bresenham line from the stroke's previous pixel to each new one, painting only points inside the tile, so a fast drag has no gaps and a stroke that leaves the edit area paints only what it crossed. A stroke paints into the bank and tile selected when it began and keeps that bank's tiles from before it; "cancel" puts them back. The picker takes the color index under the pointer on start and on every move, and the tool returns to Pencil when its stroke ends. Edits change cart directly, so Run (cart.ppu), Save and Export (cart.files) and the Load prompt (015) see them. A stroke event never redraws: when it changed the bank's tiles or the selection, Swift requests one animation frame and redraws both canvases there, so drawing costs at most one full redraw per display frame (a median of 5 ms at iPad Pro 11" and 6 ms at 12.9" landscape sizes, 8–10 ms at worst of 40, in Playwright's WebKit on a Linux CI machine; not yet timed on an iPad). The recovery copy (016) still holds only main.lua and the name, so it is now kept while those differ from the saved cart rather than while anything differs; an art-only edit no longer offers a restore that would bring nothing back, and art edits since the last Save are lost on a reload or a frozen tab until T19.
Alternatives: interpolating in JS (JS would decide which pixels a stroke covers); a redraw per pointermove (up to four full redraws per frame with Pencil); a redraw flag checked in frame() (ties the art view to the game loop); dirty rectangles (more code; a full redraw per frame fits); Pencil-only drawing (owner chose both); palm detection by contact size (not reliably reported by WebKit on iPadOS); dropping or clamping positions outside the canvas (a chord or a painted border the pointer never crossed); a sticky picker (an extra tap back to Pencil after every pick); color 0 by default (invisible in the sprite bank); keeping the copy while anything differs (its restore would bring back code only and silently drop the art).
