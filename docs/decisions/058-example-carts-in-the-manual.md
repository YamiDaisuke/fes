# 058 Example carts in the manual
Status: accepted (2026-11-18, T54)
Context: M14's Examples section has six complete carts that must run on the art they assume, and one has two files. Decision 057's spec boots one main.lua per example through window.testCartMainLua. A new cart's art is blank (041), and the built-in demo had one sprite tile, too few to animate.
Decision: The examples use the built-in demo's art: background tiles 0 (floor) and 1 (wall), sprite tile 0 (the player facing right) and sprite tile 1, a second step of the walk added to DemoCart for the animation example; the demo's own code doesn't draw it. The section tells the reader to type an example into the demo and save it under a new name, or to draw those four tiles on a new cart first. Each example is a section with id example-<name> whose code is in pre elements with data-example="<name>". An example with more than one file has one pre per file, each with data-file="<file name>"; a pre without data-file is main.lua. Opening an example in FES (T56) reads the pres the same way. web/tests/manual-examples.spec.js groups the pres by data-example. A one-file example boots through testCartMainLua as before. An example with more files is imported as a .fes holding the demo's art and its files with the existing loadCodeFiles helper, opened with Edit and started with Run, so no boot hook takes a table of files; the spec therefore runs in a persistent WebKit context, where OPFS works. The require entry's example follows the same rule and is now tested. The spec holds →, ↓ and A for 60 frames, then ← and ↑ for 60, because the examples read the whole D-pad.
Amends: 057 (multi-file examples are tested too; the spec also holds ↓ and ↑).
Alternatives: window.testCartMainLua taking a table of files (Swift code that exists only for one spec); adding the second file through New file and the code editor (more steps for the same result); leaving two-file examples untested (the require example could break unnoticed); asking the reader to draw a second sprite tile (the example would blink when opened with the demo's art); animating with palettes instead of tiles (not what the example teaches).
