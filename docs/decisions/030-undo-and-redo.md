# 030 Undo and redo
Status: accepted (2026-11-13, T23)
Context: PLAN's T23 makes every Art view edit one undo step, with redo until the next new edit, a history cleared when another cart opens and a fixed limit (owner, PR #51, answer 7); gestures come later (answer 6). Edits are a stroke, a fill, a flip, a paste, a keyboard Paint pixel, a palette assignment (028), each main color picker value (029; a drag sends many, and no event marks its end) and Reset. CodeMirror already has its own undo for code. A TileBank is 2,048 UInt32s, 8 KB.
Decision: Editors/CartArt.swift holds the art a cart's Art view edits (main palette, both tile banks, both palette banks), read and written as Cart.art; name, main.lua and the map are not in it, so Art undo never touches code and CodeMirror's history stays separate (it already resets on cart open, as setCode builds a new state). Editors/ArtHistory.swift keeps undo and redo stacks of steps, each a name ("stroke", "fill", "pixel", "horizontal flip", "vertical flip", "paste", "palette color", "main color n", "main palette reset") and the CartArt from before the edit. Recording an edit whose art equals its snapshot adds nothing; any other edit clears redo; past 100 steps the oldest is dropped. Snapshots share unchanged arrays by copy-on-write, so a step costs about 8 KB for a tile edit and under 1 KB otherwise, at most about 0.8 MB. Every edit site records its step where it writes the recovery copy (025), through one App function that does both; a stroke records at its end or drop. Picker values merge into the newest step while it has the same name and nothing else happened; the picker's click, which fires each time it opens, any other step, undo and redo stop the merging, so one picker session is one step. Undo and Redo first drop a held stroke, so undo during a stroke takes back that stroke. They restore the art exactly, so the unsaved test (cart != lastSavedCart) and the recovery copy need no change; each writes the copy once. The selection doesn't move. The history clears when a cart opens or a recovery copy is restored, not on import (which opens nothing) or Save, and it isn't stored, so a reload loses it. The tools column starts with a History group of Undo and Redo buttons, aria-disabled (not disabled, so focus stays) when empty, labelled "Undo fill" by Swift; ⌘Z and ⌘⇧Z act only while the Art view is shown, with preventDefault, so CodeMirror keeps them in Code. The status announces "Undid fill.", "Redid fill." or "Nothing to undo.". Reset main palette no longer asks first. Not yet checked on an iPad: whether Safari delivers ⌘Z to the page.
Alternatives: per-pixel diffs (each tool reports its changes; more code for memory we don't need); whole-Cart snapshots (undo would roll back code); 256 or unlimited steps (more memory wasm never returns; the owner asked for a limit); one step per picker value (dozens of presses per drag); ending a picker session on change, blur or a timer (WebKit fires change on every value and never blurs on iPad, 029; a timer splits slow drags); one history shared with CodeMirror (JS would own editor state); restoring the bank or selection per step (more state); storing history in the recovery copy (a new format and up to 0.8 MB in localStorage); disabled buttons (focus is lost on the last undo); Ctrl-Z too (FES targets iPad, where CodeMirror's Mod is ⌘); keeping Reset's confirm (undo now covers it).
