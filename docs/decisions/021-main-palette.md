# 021 Main palette in the cart
Status: accepted (2026-11-05, T16)
Context: Decision 004 left the 64-color palette a generated placeholder (also the colors of 006's goldens), and 013 planned a per-cart copy with a format bump. In PR #51 the owner chose Lospec's "Z64" by Jehkoba (https://lospec.com/palette-list/z64) as the default, and rejected the word "master" (PR #51 renamed it in the docs; this task renames MasterPalette and master indices in the code).
Decision: Console's MainPalette is a value of 64 Colors; MainPalette() is Z64 in Lospec's order, and an index wraps to 6 bits as in 004. PPU and Cart each carry one; PaletteBank holds only main palette indices, and the PPU looks colors up in its own main palette. The cart file main-palette.hex is 64 lines of rrggbb, line n being color n − 1: Lospec's .hex download loads as is. Hex is written lowercase and read in either case; no #, spaces or blank lines; duplicate colors are allowed; anything else refuses the cart naming the file and line, as 013's files do. cart.json is format 2, which requires main-palette.hex. A format 1 cart, from OPFS or a .fes, loads with Z64, ignores the contents of a main-palette.hex (it must still be valid UTF-8, because both read paths decode every Cart.fileNames entry before the format is known, so a non-UTF-8 one refuses the cart), and is written as format 2 on its next save or export. The file is in Cart.fileNames before palettes.pal, so a .fes now holds seven files and 020's checks cover it. Goldens are recorded in Z64. This replaces 013's "Later" line.
Alternatives: a global palette with a per-cart override (two sources of truth); reading main-palette.hex in format 1 carts when present (a save interrupted before cart.json would mix formats); GIMP .gpl or #rrggbb lines (the owner chose HEX, and a Lospec download should drop in); the palette inside cart.json (one long line, no per-color diffs); PaletteBank.color(palette:index:in:) (threads the palette through a type that doesn't use it); parsing hex text at startup for the default (Console can't use Storage's parser, and it adds a failure path).
