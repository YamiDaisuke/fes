# 049 The code view as an old computer
Status: accepted (2026-11-16, T46)
Context: M12 restyles FES as a pixel-art device (045). The owner's brief asks for a code editor like an Apple II or Commodore screen; the owner chose C64 indigo for it (decision 5, issue #115). CodeMirror 6 stays unforked (015), the legacy Lua mode names only keywords, strings, numbers, comments and Lua's standard library, and iPadOS draws the main text selection itself.
Decision: The editor's colours are twelve --code-* tokens on :root in web/style.css; the syntax ones point at the pastel tokens, and errors use --coral and --ink. web/code-editor-look.js turns them into one EditorView.theme (dark) and one HighlightStyle (@lezer/highlight tags: keyword, string, number, comment, and the standard library as standard(variableName)); everything else is the text colour. Code text is at least 7:1 on the screen and on the current-line band, comments at least 4.5:1, and a Playwright spec measures this in the running editor. Code is Departure Mono at 22/28 set on .cm-scroller; every gutter has a whole-pixel width (the lint gutter is 22 px, not 1.4em; the fold gutter 14 px) so each line starts on a whole pixel. The cursor is a 14 px block in --code-cursor with mix-blend-mode: difference, so the glyph under it shows inverted; it blinks with CodeMirror's steps(1) animation, off under prefers-reduced-motion. The editor sits in a sunken well bezel without clip-path, so lint tooltips aren't clipped; its focus ring is the butter outline with an ink ring, on :focus-within. The row above holds the cart name and the file keys, then the file tabs as paper disk labels with a sky stripe, the shown one butter; DOM order is visual order. The code error is an ink-on-coral strip under the editor. On iPadOS the main selection is the system highlight, which CSS can't recolour (WebKit bug 273951); --code-selection colours CodeMirror-drawn selections elsewhere.
Amends: 015 (theme and font), 039 (the file actions now come before the tab strip, in the row above it).
Alternatives: colours hard-coded in the JS theme (two places to tune); CSS rules against CodeMirror's classes (lose to its scoped base theme); 1ch cursor width (WebKit reports 13.98 px for a 14 px advance); an outline or underline cursor (less like the machines in the brief; the difference block was verified in WebKit); a stepped clip-path on the bezel (clips tooltips); our own Lua tokenizer to colour function calls (new code for one colour); a one-colour green or amber syntax (keywords and strings hard to tell apart); one row with tabs between name and actions (PHASE2 asks for two; tabs get the full width).
