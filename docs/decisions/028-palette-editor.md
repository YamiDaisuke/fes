# 028 Palette editor
Status: accepted (2026-11-13, T21)
Context: PLAN's T21 shows the 8 background and 8 sprite palettes and the 64 main palette colors as buttons whose labels name the entry and its color: select an entry, then tap a main color to assign it, and selecting a palette makes it the preview palette. The Art view's tools column (022) is 256 px wide, too narrow for 8 swatches of 44 px per row, and already scrolls in portrait. Sprite color 0 is always transparent (004, 008).
Decision: A Palettes toggle button (aria-pressed) at the top of the tools column swaps the edit area for a palette panel in the same grid area; the sheet and tools stay visible, so a recolor shows on the sheet at once. Toggling drops a held stroke, as leaving Art does (023). The panel shows the selected bank's 8 palettes as an 8 × 8 grid of entry buttons, one palette per row, and the 64 main colors as an 8 × 8 grid in index order, all 44 px. An entry is (preview palette, color), so selecting one sets ArtSelection.previewPalette and .color: the Palette buttons, the color strip and the pencil follow, and no second selection exists. A main color tap assigns it to the selected entry at once and writes the recovery copy once (025); it is one cart change, so T23 can undo it as one step. The main color assigned to the selected entry is aria-pressed. Labels are built in Editors: "Sprite palette 3, color 5: main color 42, #49b893", "Sprite palette 3, color 0: transparent", "Main color 42, #49b893", with lowercase hex from Color.hexCode. Sprite color 0 is drawn as the checker and can be selected (to draw transparency), but while it is selected the main color buttons are disabled and a hint says it is always transparent; its stored index is never changed. Swift creates the 128 buttons at start and redraws them only while the panel is shown, so strokes don't pay for them. The panel follows the tools column in DOM order, so Tab reaches the tools first.
Alternatives: swatches in the tools column (32 px targets, and a taller column); a collapsible section in the column (same width, pushes the Tile and Pixel controls down); a panel spanning the edit area and tools (hides the bank buttons and the toggle); all 16 palettes at once (128 entry buttons, doesn't fit); a separate "entry being edited" selection apart from the drawing color (two selections to keep apart); assigning with a confirm step (undo comes in T23); 128 buttons written in index.html (near-identical lines); arrow-key grid navigation with a roving tabindex (more code; VoiceOver users move by heading and group); letting the editor set sprite color 0 (the PPU ignores it, so the edit would do nothing visible).
