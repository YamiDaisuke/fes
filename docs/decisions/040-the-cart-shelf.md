# 040 The cart shelf
Status: accepted (2026-11-15, T37)
Context: M11 replaces the Code view's cart list, which loaded a cart on tap, with a full-screen shelf that later tasks give delete (T38), labels and D-pad selection (T40). Export used to take the open cart and the name field, so a cart could only be exported by opening it.
Decision: The shelf is a fourth view (`ShownView.shelf`, toolbar button "Carts"). Swift builds its list on every refresh: a first entry "Built-in demo" (data-folder "") and one button per saved folder, sorted by name. Tapping an entry selects it (aria-pressed; Swift keeps the selected folder, "" for the demo) and loads nothing. Play and Edit load the selection (asking before discarding unsaved changes; the demo opens fresh with no folder) and then run it or show its code; Export reads the selected saved cart from storage and exports that, so the open cart's unsaved edits are never exported; Import stays as it was. Every action waits for earlier storage work (T31), the demo too, so a save that is still writing can't mark the newly opened cart as unsaved. The read before navigator.share is short enough to stay inside WebKit's transient activation window. Damaged entries stay selectable and their actions say why they can't be read, until T38. The cart name field stays in the Code view because Save reads it.
Alternatives: load on tap (no target for delete or D-pad selection); a static demo entry in HTML (cleared by each refresh, and specs can't tell when saved carts are listed); reading the whole cart on selection so Export needs no await (reads every cart a user taps past, goes stale under a save); exporting the open cart (exports unsaved edits under a saved cart's name, and can't export a cart without opening it); an entry named "Demo" (clashes with the demo saved under its default name).
