# 046 The control deck
Status: accepted (2026-11-16, T43)
Context: T43 applies the look (decision 045) to the app's toolbar for the first time. The views become toggles, a Game switch is new, a power LED appears, and the status line must fit beside the keys on an iPad in portrait.
Decision: #toolbar is a .plate holding, left to right, an aria-hidden .power-led, a .switches group named View with Carts, Code, Art and Game as .key.key-nav toggles, Run and Save as .key-go, Set label (game view only), and #cart-status as a .readout. Every id and accessible name from before stays, so specs and VoiceOver find the same controls. Each switch is its own Tab stop with no toolbar role, because the arrow keys belong to the controller. show(_:) sets aria-pressed on show-<view>, and CSS only reads it. Game resumes the running cart when it was started from the opened cart, and otherwise runs the opened cart: runningCartIsOpenedCart is set by runCart and cleared by openCart, because opening a cart leaves the old RunningCart in place. The LED state is a body data-led attribute (off on the shelf or when the running cart is not the opened one, error while runningCart.error is set, otherwise on), so every .power-led (the deck's, and T44's under the bezel) follows one value. The readout is a fixed two-line box that clamps with an ellipsis and carries the full message in its text and title: messages run to about 100 characters, and a fixed height means a message never rescales the game canvas. The deck wraps, and the readout needs 120u (about 30 characters over its two lines) before it shares the keys' row, so where the keys leave less (the game view in portrait, the code, art and game views at 744 or 678 px) it takes its own full-width row under them; landscape decks stay one row, and the deck's height then depends only on the width and the view, never on a message. A wrapped row starts on whole pixels like the first, and 600 px wraps Set label too instead of overflowing. A focused deck key gets an ink frame outside the butter ring, because butter on the lilac plate is about 1.3:1. Centring is fine inside the deck because every box is a whole number of --u, so centring offsets are whole pixels. Until T44, T46 and T47 restyle them, the code, art and game views keep a black background so their white text stays readable on the shell.
Alternatives: new #view-* ids (would break about ten specs for no gain); role="toolbar" with roving focus (conflicts with controller arrow keys); a fresh RunningCart in openCart (runs cart Lua on every open); a disabled Game key until Run (dead key with no visible reason); a one-line readout (about 20 characters in portrait); a readout that always shares the keys' row (24 px, one character a line, at 678 px); a media query on the viewport width (the space the keys leave depends on the view, which flex-basis measures directly); a readout that wraps freely (the deck's height, and so the canvas scale, would jump with each message).
