# 054 App icon, boot animation and theme color
Status: accepted (2026-11-17, T50)
Context: M12's last device task (docs/PHASE2.md, T50): the Home Screen icon, a boot animation while App.wasm loads, and the status bar colour. FES boots into the shelf (044), so the game bezel PHASE2 named is hidden at boot.
Decision: The status bar colour is --shell, in the manifest's theme_color and background_color and in the theme-color meta; one colour, as FES has no dark mode; a spec keeps all three equal to the token. iPadOS draws no launch screen from background_color. The boot animation plays on the shelf's preview screen: #boot-logo ("FES", --pink, Pixel Operator 8 at 64 px) sits under the transparent preview canvas in a one-cell grid, so it covers no control and a selected label covers it. While body has data-booting, and only under prefers-reduced-motion: no-preference, the logo is revealed one font-pixel row at a time (clip-path, steps(8), 640 ms) and .power-led blinks (steps(1), 320 ms). boot.js removes data-booting after instantiate (which runs main) once the logo's animation has settled, so the boot ends at most 640 ms after load, never delays the frame loop, input or the restore dialog (top layer), never replays on a view switch, and ends at once when the logo isn't shown (reduced motion, or a testCartMainLua boot that shows the game). The app icon is a 16×16 grid in scripts/make-icons.js whose colours are read from web/style.css's tokens, written with web/tests/png.js's encodePNG at 152, 167 (the sizes iPads ask for), 180 and 512, each a whole number of pixels per cell so iPadOS never resamples pixel art; each has an apple-touch-icon link with sizes, and the manifest lists all four. No maskable icon: iPadOS doesn't use it, and the art keeps a two-cell margin inside its opaque square.
Amends: 019 (icon sizes and colours), PHASE2 T50's sketch (the shelf preview instead of the bezel; no explicit testCartMainLua branch).
Alternatives: the game bezel (hidden at boot); a full-page boot screen (covers controls after load and needs skip handling); drawing the logo from Swift (can't run while the wasm loads); a status-bar-style meta (black-translucent puts white text on lilac); colours copied by hand into the script (drift when the owner retunes tokens); per-device apple-touch-startup-image launch screens (a dozen generated images; revisit if the owner wants a lilac launch).
