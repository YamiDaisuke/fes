# 056 The manual and the Help view
Status: accepted (2026-11-18, T52)
Context: M14 adds a manual that takes a beginner from "what is this" to a small game (docs/PHASE2.md). It must work offline, cost nothing at boot, never unload the open cart, and also be readable on its own, for example from a link on a phone. The owner chose Pixel Operator 8 at 16 px for its text, with the system font as a fallback token (decision 7, issue #121).
Decision: The manual is one static page, web/manual/index.html, with manual.css and a small manual.js. It links ../style.css for the tokens, fonts and components, and manual.css undoes the app shell's html and body rules, as look.html does. A fifth view, Help (ShownView.help, a Help key last in the deck's View switches), holds one iframe titled "FES manual". Swift sets the iframe's src to manual/ the first time Help is shown, so boot loads none of the manual. Help is hidden with display: none like every view, which keeps the manual's document and scroll position (checked in WebKit) and leaves the cart and the editors untouched. The cart doesn't run while Help shows. Opening Help focuses the iframe, so VoiceOver announces its title and the keyboard scrolls the manual. Leaving Help is any other deck key, which focuses its own view as before. The build's precache list names every file as ./path, and a folder's index.html as the folder (./ and ./manual/), because those are the URLs the app and links request. So the manual opens offline in the app and on its own. Body text is --type-manual: Pixel Operator 8 at 16 px on 24 px lines (an even 4-font-pixel gap, per 045), through --font-manual. Setting --font-manual to --font-system is the fallback. Code blocks use --type-code on the code editor's indigo. Inline code stays in the body font on the same indigo, because Departure Mono's 28 px glyph box doesn't fit a 24 px line. The text column is round(down, 68ch, var(--u)) wide and left-aligned, so it stays on whole pixels. The contents are one details element in a nav: open as a sticky column in landscape, closed above the text in portrait. manual.js sets it from the orientation query and shows a Back to FES link only when the page isn't inside a frame. Section ids are fixed for the tasks that fill them: welcome, first-cart, console, buttons, code-editor, drawing, carts, keeping-carts-safe, lua, api (with api-<name> entries), examples, troubleshooting, coming. The fifth key moves Set label onto the readout's row in the game view at 678 px wide, without changing the deck's height, and moves the readout under the keys on the shelf at 678 px.
Amends: 019 (folder URLs in the precache list instead of a hand-added ./); 046 (five View switches).
Alternatives: src set in the HTML with loading="lazy" (a hidden iframe still loads); src="manual/index.html" (the manual's own URL, manual/, would not be cached); a dialog or a new window (a dialog traps focus over the editors, and a window leaves an installed app); visibility: hidden instead of display: none (a special case with no gain); Departure Mono for inline code (uneven line heights); two copies of the contents for the two orientations (they would drift); a separate tokens stylesheet (changes every page for one new reader).
