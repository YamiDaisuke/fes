# 029 Editing main colors
Status: accepted (2026-11-13, T22)
Context: PLAN's T22 changes the selected main color with the iPadOS color picker, an <input type="color"> (owner, PR #51), so every palette entry using it changes too, and resets the cart's main palette to the default (decision 021). Decision 028 makes the main color assigned to the selected entry the aria-pressed one. In WebKit on iPadOS, every color the picker reports, including each step of a continuous drag, sets the input's value and fires input and then change (WKFormColorControl.mm, ColorInputType::didChooseColor). Closing the popover fires no event and, on iPad, doesn't blur the input (WKContentViewInteraction.mm blurs only on small screens). The picker has no Cancel. Not yet checked on an iPad.
Decision: The palette panel has a labelled <input type="color">, "Edit main color n", which edits the main color assigned to the selected entry and is disabled while sprite color 0 is selected. Swift listens to its input event only. It reads the value with Color(hexCode:), which accepts # and 6 ASCII hex digits in either case and refuses anything else, leaving the cart unchanged and saying so in the cart status. Each accepted value is the edit: it sets cart.mainPalette at once and redraws at most once per animation frame (023), so the sheet, the entries and Run show it while the picker is still open. Closing the picker keeps the last color. The recovery copy (025) is written 500 ms after the last accepted value, and at once when Run starts while that write is pending, because a drag has no end event and a frozen cart stops timers. "Reset main palette" asks with confirm (no undo before T23), puts back Z64, keeps each entry's main color number, writes the recovery copy, and is disabled while the palette is already Z64. Save, Export and the recovery copy write main-palette.hex through Cart.files as before (021).
Alternatives: committing on change (WebKit fires it on every step) or on blur (never fires on iPad); a separate main color selection (028 rejected a second selection); a hidden input opened with showPicker() from a JS module (more code, and a hidden control VoiceOver could reach); writing the copy on every value (up to one per display frame during a drag, which 025 forbids for pointermoves); Reset without a confirm (up to 64 custom colors lost with one tap and no undo).
Later: T23 groups a picker session's values into one undo step, and may drop Reset's confirm.
