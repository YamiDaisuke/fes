# 020 .fes archive, export and import
Status: accepted (2026-11-05, T15b)
Context: Decision 013 shares a cart as a zip of its folder named <cart name>.fes. SPEC puts zip export and import in Storage, no zip library is approved, and an imported file is untrusted input. In a Home Screen web app, <a download> strands the user on an "Open in…" screen (WebKit bug 290847), and iPadOS can't register a .fes type.
Decision: Storage writes and reads store-only zips (method 0, no zip64, encryption or data descriptors) by hand, with one CRC-32 shared with the golden PNG writer. Export writes the six cart files at the top level in Cart.fileNames order, dated 1980-01-01 so the bytes are reproducible without Foundation. Import refuses files over 8 MiB (the Lua memory cap) before reading them, then refuses archives without an exact end record, whose end record's central-directory size or offset is not where the directory is, multi-disk, over 64 entries, encrypted, compressed, with a data descriptor (flag bit 3, so zips Python's zipfile streams to a pipe are refused too), out of range, with a CRC mismatch, with a local header whose name, flags, method, date, time, CRC or sizes differ from its central header (Files and other streaming unzippers read local headers, so the two must show the same cart), with duplicate names, or whose entries, in central-directory order, don't run back to back from byte 0 to the central directory (so no overlaps, which also bound memory at 8 MiB, and no gaps, prepended bytes or hidden local entries a streaming unzipper would see; zip -0, 7z -mx=0 and Python's ZIP_STORED all write this way). Extra fields may differ between the two headers, as Info-ZIP writes them. Entry names are only compared with Cart.fileNames, never used as paths; other entries are ignored as 013 ignores unknown files, except a cart file's name in another case or with a trailing /, which is refused because unzipping in Files (case-insensitive) could keep it in place of the real file. Known files must be strict UTF-8, then Cart(files:) validates as for OPFS. An imported cart always goes into a new folder with its name unchanged and is not opened; the open cart is never touched. Export uses the editor's code and the name field, names the file <name>.fes with characters Files rejects replaced by - and a leading . replaced so Files doesn't hide it, the name cut to 200 UTF-8 bytes on a character boundary and trimmed, and cart.fes if nothing is left, refuses (T15c) a cart whose archive would be over 8 MiB, since import would refuse it, and hands it to navigator.share in a Home Screen app and to <a download> in a tab. The import picker has no accept filter.
Alternatives: a zip library (new dependency for about 120 lines); deflate (an inflater in Swift); CompressionStream in JS (format logic in JS); renaming duplicates on import (breaks an exact round trip and differs from Save); replacing a same-named cart (silent data loss); <a download> everywhere (dead end in a Home Screen app); accept=".fes" (iPadOS may grey out unknown types).
